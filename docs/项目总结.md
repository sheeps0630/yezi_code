# 椰吃家项目总结

> 文档用途：作为项目基础功能完成后的交接、维护和后续迭代参考。
> 当前基线：**v0.2.0**，Git 标签 `v0.2.0`，主分支 `main`。
> 总结日期：2026-11-13。

## 1. 项目简介

椰吃家是一个面向个人和家庭的全栈演示应用，帮助用户决定“今天吃什么、喝什么”，并提供菜谱、收藏和家庭资料管理。当前版本已经完成主要页面与核心交互，适合作为功能原型和后续开发基线；地图、账号和数据存储仍是演示级实现，不应视为已具备生产部署能力。

## 2. 已完成的基础功能

| 场景 | 已有能力 |
| --- | --- |
| 出去吃 | 按权重抽取自定义美食类别；推荐周边示例门店；支持喜欢/讨厌类型、排除已看结果、收藏及查看本轮已看。 |
| 自建转盘 | 自定义转盘选项及权重，默认权重为 1；支持保存和切换多个本地方案；转盘停止后选项文字保持正向。 |
| 在家做饭 | 多选素菜、肉菜、甜品、海鲜、汤羹；搜索、折叠和多选食材标签；按筛选生成菜单并查看固定菜谱。 |
| 喝什么 | 支持外出觅饮和在家自制；外出可按饮品类别推荐示例饮品；自制提供 14 款一人份配方，酒精饮品明确标示及安全提示。 |
| 收藏与已看 | 吃、喝场景均可收藏和置顶；收藏按置顶/收藏时间排序，删除前二次确认；“已看”只记录当前场景本轮结果。 |
| 个人与家庭 | 编辑昵称、手机号；从本机选择头像；管理收藏、家庭菜谱和家庭成员；菜谱收藏及家庭菜谱可进入详情页。手机号只作为联系方式，不关联其他账号。 |
| 界面 | 采用椰子主题配色，兼顾较窄屏幕的布局。 |

静态数据目前包括 30 道菜品、30 份菜谱、15 条饮品示例及 15 家门店示例。饮品自制配方位于前端固定数据模块中。

## 3. 技术栈与代码结构

- **前端**：Vue 3、TypeScript（严格模式）、Vite、Vue Router。
- **后端**：Java 17、Spring Boot 3.2.5、Maven；REST API 统一使用 `/api` 前缀及 `{ code, message, data }` 响应结构。
- **当前存储**：后端以 `ConcurrentHashMap` 等内存结构保存演示用户资料和收藏；静态菜谱等数据以 JSON 保存。转盘方案和头像保存在浏览器本地。
- **页面路由**：`/` 吃什么、`/drink` 喝什么、`/profile` 我的、`/recipes/:dishId` 菜谱详情。

主要代码入口：

- `backend/src/main/java/com/yechijia/controller/`：HTTP 接口。
- `backend/src/main/java/com/yechijia/service/`：推荐、做饭、收藏等业务逻辑。
- `backend/src/main/java/com/yechijia/repository/`：静态数据装载及内存用户存储。
- `backend/src/main/resources/data/`：菜品、菜谱、饮品和门店 JSON 数据。
- `frontend/src/views/`：页面视图。
- `frontend/src/components/`：做饭、周边美食、收藏等交互组件。
- `frontend/src/api/`：请求封装、前后端类型和饮品配方数据。

## 4. API 功能域

后端默认监听 `18080`，前端 Vite 开发服务器默认监听 `5173`，开发代理将 `/api` 请求转发至后端。

| 功能域 | 路径 |
| --- | --- |
| 出去吃 | `/api/eat-out/categories`、`/api/eat-out/types`、`/api/eat-out/recommend` |
| 在家做 | `/api/cook/categories`、`/api/cook/ingredient-types`、`/api/cook/dishes`、`/api/cook/menu`、`/api/cook/recipes/{dishId}` |
| 喝什么 | `/api/drink/categories`、`/api/drink/recommend` |
| 个人与收藏 | `/api/user/profile`、`/api/user/favorites`、`/api/user/favorites/{favoriteId}/pin` |
| 家庭资料 | `/api/user/family-recipes`、`/api/user/family-members` |

详细 HTTP 方法、参数和 DTO 定义以对应 Controller、DTO 和前端 API 模块为准。

## 5. 本地开发与打包

环境要求：Java 17、Maven 3.9.x、Node.js/npm。请在两个终端分别运行前后端。

**终端一：构建并运行后端**（在项目根目录执行）

```powershell
cd backend
mvn package
java -jar target/yechijia-backend-0.2.0.jar
```

**终端二：启动前端开发服务器**（在项目根目录执行）

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`。前端生产构建与类型检查：

```powershell
cd frontend
npm run build
```

目前已生成的 v0.2.0 发布包为 `releases/yechijia-v0.2.0.zip`；后端可运行 JAR 为 `backend/target/yechijia-backend-0.2.0.jar`（需要先运行 Maven 打包才能重新生成）。

## 7. 当前边界与风险

1. **重启会丢失用户数据**：收藏、个人资料、家庭菜谱和家庭成员位于后端内存中；头像与转盘方案位于当前浏览器。它们没有跨设备或跨用户同步能力。
2. **没有用户系统**：当前为固定演示用户，没有注册、登录、授权或多用户数据隔离。
3. **地图和推荐数据是桩数据**：门店、距离、评分及附近推荐均为示例；还未接入真实定位和地图服务。
4. **演示配置不适合直接上线**：CORS 默认允许所有来源，尚无生产环境配置、安全策略及部署运维方案。
5. **自动化质量保障不足**：后端测试源码、前端组件/端到端自动化测试和持续集成流程仍需建立。
6. **素材和数据维护依赖人工**：菜谱与饮品是静态内容，尚无运营后台、内容审核或数据更新流程。

## 8. 建议的后续迭代顺序

### P0：确定产品化方向

- 明确目标平台、用户范围、部署方式，以及是否需要多用户和跨设备同步。
- 明确是否引入真实地图/定位、登录方式、隐私政策和手机号处理规则。

### P1：提高数据可靠性

- 设计用户身份及数据模型；选择数据库并完成收藏、家庭资料等数据迁移。
- 区分开发、测试和生产配置；生产环境收敛 CORS 来源，管理密钥和个人信息。
- 为收藏、置顶、重复提交、删除和用户隔离补充后端自动化测试。

### P2：补齐交付与质量保障

- 增加前端组件/端到端测试和 API 合约测试，并在 CI 中运行构建与测试。
- 补充生产部署说明、环境变量示例、健康检查、日志和数据备份恢复流程。
- 根据真实用户反馈迭代推荐规则、菜谱内容和移动端交互。

上述条目是建议，不代表已实现或已确定的产品决策；开始相关迭代前应先确认需求与数据边界。

## 9. 维护约定

- 新功能和修复通过独立 Git 提交记录；版本发布时同步更新后端、前端版本号及 `CHANGELOG.md`，并创建语义化 Git 标签（如 `v0.3.0`）。
- 不提交 `node_modules/`、`frontend/dist/`、`backend/target/`、本机 IDE 设置、密钥或包含个人数据的文件。
- 完成改动后至少执行前端 `npm run build` 和后端 `mvn package`；新增业务逻辑时同步添加自动化测试。
